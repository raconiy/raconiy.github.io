PhysStream: Streaming Physics-Grounded Video Generation with Structured Scene Memory and Fine-Grained Motion Control

Chuhao Chen et al. · arXiv:2609.17521v1 · First submitted: 2026-09-15 · Read version: v1

PhysStream 将在线估计的深度位置图与对象跟踪图作为结构化 scene memory，配合稀疏速度增量控制流式生成中的物体运动。

At a Glance

  1. 速度增量表达物理控制量，用户可以在生成中途插入控制，而不是预先给完整轨迹。
  2. Depth-Anything-3 提供位置图，SAM2 传播对象 mask；两类历史条件只来自已经生成的帧。
  3. 论文在合成和真实场景显示控制响应与物理合理性提升，但当前核心设定是静态相机和桌面物体。

Problem Setup

01 · The Problem: Physical Control in a Streaming Generator

PhysStream 研究 image-to-video 生成中的交互控制：给定一张初始图像，用户在任意时刻对一个对象施加稀疏的速度增量，模型要继续生成后续帧，并让碰撞、遮挡和对象身份保持合理。相比直接画像素轨迹，速度增量更接近物理量，控制信号不必提前覆盖整段视频。

论文的范围需要明确：核心实验是静态相机下的刚体桌面场景，目标是检验结构化历史是否能帮助因果生成，而不是解决所有现实世界动力学。

Method

02 · Method: Motion Signal and Structured Scene Memory

模型首先接收初始 RGB、当前速度增量条件和过去生成帧的两类历史证据。位置图把最近帧的深度和相机内参转换成归一化三维位置；tracking map 由 SAM2 根据首帧目标 mask 在生成视频中传播对象身份。这样，后续帧不仅看到颜色，还能看到对象在空间中的位置和“哪个像素属于同一对象”。

位置图和 tracking map 都是从已生成历史在线估计的，不把未来真值泄漏到当前帧。作者采用 one-frame temporal shift 与 causal attention，使每个 noisy latent 只读取前一帧或更早的条件。每一步生成后，VAE、深度估计器和 SAM2 增量更新 memory，单步更新开销不随总视频长度增长。

Training

03 · Training and Inference

训练分两阶段。第一阶段在 Wan2.2-TI2V-5B 上加入速度增量条件，先学会根据物理控制生成视频；第二阶段转为 causal autoregressive teacher-forcing，并额外加入从历史帧估计的位置图与跟踪图。条件都通过 VAE latent 的 channel concatenation 注入，并配合时间移位保证因果性。

推理时流程是：解码新帧 → 用 Depth-Anything-3 估计最近窗口的位置图 → 用 SAM2 更新多对象 mask → 将这些结构化条件缓存起来 → 生成下一帧。论文使用 49 帧训练窗口，但长时序测试扩展到 301 帧；外观会逐步漂移，控制响应仍能维持。

Experiments

04 · Evidence: What the Memory Actually Buys

作者对比 Stage 1、仅速度条件的 causal 模型、加入位置图、加入 tracking map 以及完整模型。位置图主要帮助深度位移较大的对象：在最困难的 top-10% 对象上，Traj-ADE 优势达到 15.5%，全体对象的差距约为 2.1%。tracking map 则决定控制信号能否跟随对象移动；在 zig-zag 测试中，只有含 tracking map 的配置完成完整转向。

长时序 benchmark 的 tracking-map 消融显示，默认设置在 101 帧以后成功响应率为 90.3%，完全去掉 tracking map 后降到 85.0%。系统未经蒸馏时单个 49 帧片段约 66.3 秒、0.74 FPS、峰值显存 56.8 GB；4-step 蒸馏和更快深度模型后速度提升到约 3.4 倍。

这些结果支持的结论是结构化历史能改善对象级控制和几何困难运动；它们不能证明模型学到了通用物理定律，也不能直接外推到移动相机、复杂非刚体或开放世界。

Discussion

06 · Limits and Connection to Our Direction

PhysStream 对我们的启发不在于直接照搬物理控制，而在于它把 memory 设计成“下一步预测真正需要的结构证据”：位置图回答对象在哪里，tracking map 回答它是谁。对于语义增强的流式重建，可以考虑把对象语义或开放词汇特征作为历史条件，但必须验证它是否改善几何或跨帧一致性。

当前局限包括静态相机假设、在线深度与分割估计的成本、长序列外观漂移，以及合成刚体数据与真实环境的差距。论文中 Stage 1 只有速度条件，且 FVD 对额外条件并不总是更好，说明“更多 memory”不等于所有指标都提升。

Reading Questions

Why is the tracking map necessary?

因为速度信号锚定首帧 mask；对象移动后，只有 tracking map 能把控制重新对齐到当前实例。去掉它后长时序成功响应率从 90.3% 降到 85.0%。

Does positional memory help every object equally?

不是。它对深度位移大的对象帮助更明显，top-10% 对象的 Traj-ADE 优势 15.5%，全体对象只有约 2.1%。

Is this a general physics world model?

不能这样表述。实验集中在静态相机、桌面刚体和少量非刚体迁移；结果说明结构化历史有助于控制，不足以证明通用物理推理。

What could transfer to LingBot-Map?

可以借鉴“把历史压成任务相关的结构条件”这一原则，例如在 memory 中保存对象语义、实例身份和几何覆盖，而不是只增加无结构 token。
