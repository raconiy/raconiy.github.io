Seek-and-View Reasoning for Multi-View Spatial Understanding

First submitted 2026-10-08 · Reading version 2610.11810v1

Vantage 让 VLM 先分析问题并规划一个与空间关系相关的视角，再用 3D foundation model 合成证据视图，辅助最终回答。它在五个多视角 benchmark 上对六个 VLM 平均提升 6.7%，且无需 fine-tuning。

At a Glance

  1. 问题相关的视角选择先于最终空间推理。
  2. 3D foundation model 外部化跨视角对齐，VLM 读取新证据。
  3. 合成视图、问题分析和动作规划各自都有失败边界。

Paper Notes

Motivation and Task

固定少量视角常让 VLM 依赖语言在不同图像之间对齐，难以找到真正能回答问题的证据。Vantage 将任务改为 seek-and-view：先问“还需要看哪里”，再回答空间关系。

输入为多视角图像和问题，输出是最终空间回答；中间还产生参考视角、问题相关方向、相机动作和合成支持视图。

Paper Notes

Reading the Two-Stage Pipeline

图 2 的 Stage 1 由 VLM 做 viewpoint-grounded reasoning：识别 anchor、目标关系和需要观察的方向。Stage 2 用 3D foundation model 根据规划动作合成新视图，并把原图、问题分析、reasoning guidance 与新视图一起送回 VLM。

这种设计把跨视角对应从纯语言推理外部化为几何证据，但合成视图质量和动作方向会成为新的误差源。

Experiments and Ablations

作者在五个 benchmark 上评估六个 VLM，报告平均准确率。Vantage 对六个模型都提升，平均增益 6.7%，且不需要微调。

消融显示问题分析、动作接口和最终上下文都重要：对 Qwen3-VL-4B，去掉 question analysis 后，MindCube-tiny 从 38.9 降到 30.0，MMSI-Bench 从 33.7 降到 26.8。不同 3D foundation backends 和视场角也会影响效果。

Paper Notes

Failure Modes and Interpretation

错误来自问题分析、视角规划、合成不可靠和最终推理四类。即使一个模型能判断两个候选布局哪个正确，也不代表它能规划有效视角并生成准确修正。

Vantage 的提升证明“主动寻找证据”有用，但不能证明 3D foundation model 的重建结果本身准确；它只在下游 VQA 中被间接评估。

Paper Notes

Transfer to LingBot-Map

Vantage 给我们的启发是 memory 不只被动读，还可以根据当前查询或几何不确定性决定“下一步需要什么证据”。在流式重建中，这可对应关键帧选择、主动视角证据或对低置信区域保留更长历史。

但 LingBot-Map 的输入流通常没有主动相机控制。第一版应把“view planning”改成被动的 evidence selection：根据当前 token 不确定性选择历史帧，再测未来帧几何是否改善。

Paper Notes

Limits and Conclusions

该框架依赖 3D foundation model 的可控视角合成、重力对齐和动作接口，且没有 fine-tuning。对复杂遮挡或生成失败场景，额外视图可能放大错误。

最重要的迁移原则是把 memory read 定义成证据需求，而不是只按最近邻读取。它与我们的语义 memory 方向互补：语义可以告诉系统“需要哪个区域”，几何一致性决定“哪个历史视图可信”。

Discussion

Reading Questions

Does Vantage update a persistent map?

不直接。它临时生成问题相关视图，主要服务多视角 VQA。

What does the 6.7% gain prove?

证明主动视角证据能改善下游空间问答，不等于重建几何被改善。

How can LingBot-Map use it without active control?

把动作规划转成基于不确定性的历史证据检索或关键帧保留。
