Keepsake: Reassessing What Should Remain in Spatial Memory

Abdul Mohaimen Al Radi et al. · arXiv:2610.06588v1 · First submitted 2026-10-05 · Read version: v1

Keepsake 不改变视频生成器和读取规则，只在固定容量内反复判断哪些历史观测已经有了足够好的替代。

At a Glance

  1. 任务是相机控制的长视频生成，memory 保存已生成的帧、相机位姿与视觉描述符，供之后回访使用。
  2. 每次把旧 memory 与新观测一起建图，按强替代数量与最相似替代计算保留优先级，超预算则删除低优先级观测。
  3. 15 条匹配的 180 秒 MemCam 轨迹中，32 项 memory 的 FVD 为 476.6，全保留 5,397 项为 734.2；但该结果不证明系统能普遍识别更可靠或更具语义价值的证据。

Paper Analysis

01 · Separate the Archive from Retrieved Context

长视频生成器的局部上下文有限，因此系统在外部保存历史，并按下一段相机轨迹取回若干帧。Keepsake 研究的是这个长期档案应保留什么，而不是每次模型输入多少 context token。限住一次读取数量，并不自动限制档案总大小。

每次生成后，新帧连同位姿和描述符成为候选记忆。完整保留会让查询成本增长，也会留下模型曾经生成的错误。FIFO 则可能删除虽旧但无法替代的视角。Keepsake 的问题是：一条旧观测现在是否已经有其他观测提供近似信息？

这里的历史来自模型自己的输出，和真实传感器流有重要区别：下一次生成使用旧输出，新的错误可能继续回写。论文输出是视频，不是估计真实场景深度和位姿；FVD、LPIPS 的改善不能等同于重建精度改善。

02 · The Update Loop in Figure 2

Figure 2 上方保留原系统流程：给定下一段轨迹，从 memory 检索条件；生成器以该条件生成一段视频；再写入 memory。Keepsake 仅替换最后的更新器 U，生成器权重、去噪设置和检索规则保持不变。

下方将旧 memory M 和新观测 N 合并成候选 V，为每个观测建一个节点。节点边权表示相机和外观的相似程度，再根据相邻强替代数量、最近替代相似度打分。若超出预算 B，按优先级删除，剩余项仍使用宿主系统原来的表示。

这是 training-free 控制器，没有新增训练 loss，也没有可学习的语义写入网络。MemCam 的描述符来自 DINOv2-Base；WorldMem 使用池化到 4×4 的 VAE latent。两者不是显式语言对齐语义，也没有对象级身份监督。

C_t = Retrieve(P_t; M_(t−1))
Y_t = Generate(Y_(t−1), P_t, C_t)
V_t = M_(t−1) ∪ N_t
M_t = U(V_t; B),  |M_t| ≤ B

03 · Building the Pose–Appearance Graph

对两个观测，相机平移距离先除以当前候选集合非零两两距离的中位数，再加旋转角项 2θ/π。全部相机位置相同时尺度设为 1，分母有 10⁻⁶ 下限。归一化让距离相对当前 bank 的空间尺度解释，但也意味着新加入较远观测可能改变旧节点间的归一化关系。

边权是 exp(−pose distance) 与截断到非负的外观余弦相似度的加权和。默认 α=0.65；强替代阈值 T=0.65。它是两个信号的软组合，不要求两个信号同时通过独立硬阈值。

K 是冗余代理，不是重投影验证，也不是实例对应。相似视角和相似全图特征通常支持互相替代，但不保证遮挡、细小物体或动态事件相同。一个罕见错误帧也可能因为找不到替代而获得高保留分。

d_p(i,j) = ||t_i−t_j|| / max(median_nonzero_translation, ε) + 2θ_ij/π
K(i,j) = α exp(−d_p(i,j)) + (1−α) max(z_iᵀz_j, 0)
c_i = Σ_(j≠i) 1[K(i,j) ≥ T]
k_i^max = max_(j≠i) K(i,j)

04 · Retention Priority and a Small Example

优先级 u_i 合并两件事：强替代越少越值得留下；即使最相似的替代也不太像，则更值得留下。默认 τ=3、β=0.5、λ=0.25。强替代数量超过 τ 后，线性项饱和，但 β/(c+1) 仍能区分高度重复的节点。

教学算例：A 有三个强替代、最近相似度 0.95，u_A=0+0.125+0.0125=0.1375；B 没有强替代、最近相似度 0.4，u_B=1+0.5+0.15=1.65。预算不足时更容易删除 A。这里表达的是替代性，不是证明 B 更清晰或更正确。

动态重评发生在每次新观测到达后，而非每删掉一个节点就重算。论文每次只计算一遍优先级，按固定排序完成该轮删除；平分先删较早插入项。因而可能出现多个相互替代的节点在同一轮一起被删，不能把它描述成具有全局覆盖最优保证的贪心算法。

宿主系统保护的观测不参与淘汰，但仍计入 B，不能作为预算之外的额外 memory。保证预算可满足需要留出足够可删节点。

u_i = 1 − min(c_i/τ,1) + β/(c_i+1) + λ(1−k_i^max)
Default: τ=3, β=0.5, λ=0.25
Higher u_i → higher retention priority

05 · Matched Evaluation and Its Scope

作者在 MemCam 与 WorldMem 各 15 条匹配的 60 秒视频上比较策略，另用 15 条 180 秒 MemCam 轨迹测试更长时间。每组内部固定初始输入、轨迹、模型、生成参数及随机种子，仅更改持久记忆更新。MemCam 使用 Wan2.1 1.3B，每段 76 帧、50 去噪步；WorldMem 为 128×128、20 DDIM 步。

下表选用附录 Table 5 的长时结果，FVD 是视频分布距离，LPIPS 是与轨迹对应真值图像的感知距离，均越低越好。Keepsake 相对全保留将 FVD 降低约 35.1%，但 LPIPS 改善只有 0.0104。两种指标反映不同性质，不能仅用较大的百分比概括所有质量变化。

FIFO 的 FVD 也低于全保留，但 LPIPS 明显更差，说明简单容量限制与保留策略的效果要分开。短时 60 秒组中，MemCam 的 FVD 为全保留 784.9、K-center 712.0、Keepsake 690.5；不同保留策略在同一预算下确实有差异。

评估规模只有每组 15 条轨迹，附录还说明 MemCam 套件参与了策略开发。WorldMem 因长期生成严重退化没有扩展到 180 秒。结果支持这些宿主和轨迹上的收益，不是任意环境的长时一致性证明。

06 · A Useful Split: Retention Gap and Selection Gap

这篇最值得借鉴的诊断是把“没存住”和“存住却没读对”拆开。Retention gap 比较完整历史的最佳证据与保留集合的最佳证据；selection gap 再比较保留集合的最佳证据与检索器实际选出的证据。它们用真值特征事后计算，不是在线控制器可以直接获取的分数。

180 秒、B=32 时，Keepsake 的 retention/selection gap 为 0.0426/0.1470；FIFO 为 0.1668/0.0646。Keepsake 保留的有用信息更多，但原检索器并没有把它用得比 FIFO 更充分。完整历史 retention gap 按定义为 0，selection gap 却达到 0.2188。

这说明扩大候选库并不自动改善实际读取；也说明仅看到最终效果提升，不能确定改进来自写入、读取还是它们的配合。对 LingBot-Map 可借鉴这个问题分解，但其隐式 KV 无法直接套用帧级 oracle 定义，需要设计匹配其预测目标的干预或探针。

07 · Does the Policy Really Select More Reliable Evidence?

作者用同一个全保留 rollout 的历史图像做 common-source 诊断，排除不同策略已经生成不同视频带来的混杂。Keepsake 的平均视点 mismatch 更高：0.3254 对 0.1256；历史内容 corruption 更低：0.4079 对 0.4871。两者都用 DINO 距离，但分别问视点相关性和历史图像保真度。

更重要的是附录敏感性分析：Keepsake 相对全保留选择的历史图像，整体 PSNR 优势为 4.629 dB；排除选择初始条件图的分歧后只剩 1.060 dB；再要求双方选中图均有至少 0.80 的 FOV overlap，只剩 0.103 dB，PSNR 与 SSIM 差值置信区间均包含零。

因此论文不能被解读为“替代性分数已经识别了更高质量证据”。整体差异依赖选择分布，包含初始图选择的贡献；在更匹配的视点条件下，证据不足以支持普遍的保真度优势。保留稀有信息与辨别错误信息仍是两个问题。

08 · Bounded Memory and Actual Runtime

旧档案最多 B 项，新一段最多 s 项，所以每次候选不超过 B+s。全两两相似度的时间与临时存储为 O((B+s)²)，排序为 O((B+s)log(B+s))；持久档案为 O(B)。只有固定 B、chunk 大小和观测尺寸后，才可称与视频长度无关。模型权重、激活与全部输出视频不包含在该预算里。

容量也不是越大越好。180 秒 MemCam 中，B=16 的 FVD 为 446.1，B=32 为 476.6；最低 LPIPS 则出现在 B=64。该扫参反映当前策略与检索器的折中，不能概括成增加容量本身有害。

端到端速度和查找时间必须分开。180 秒 MemCam 视频从 587.99 分钟降到 193.14 分钟；60 秒 WorldMem 从 12.30 降到 11.85 分钟。后者查找更快但总耗时改进很小。控制器是在线更新，不等于视频生成达到实时。

09 · Connections to Semantic Guidance and Prior Notes

Keepsake 与 MaLoW、LingBot-Map 分别落在不同位置：Keepsake 选择显式历史观测，MaLoW 把历史变为生成权重，LingBot-Map 保留并读取压缩 KV。可借鉴的是在固定预算下验证“哪些历史仍有贡献”，而非把帧级保留公式直接套到特殊 token 上。

对写入前语义融合，语义可以帮助区分内容模式，但“同类”不能直接视为可替代。两处相似墙面可能支持完全不同的位姿约束，同一物体不同侧面也可能提供互补几何。若以后做语义驱动淘汰，必须与空间覆盖、可见性和几何置信度联合，而不是只按语义余弦删除。

这篇还提示实验要固定读取器：先仅改变 memory 形成或保留，判断后续任务是否改善，再单独优化读取。否则增加参数、替换检索规则和更换历史预算同时发生，就难以解释语义具体贡献。

作者主页链接了论文，论文说明策略代码放在补充材料；本次未核实可运行的公开代码包，所以算法细节依据正文与附录，未声称完成代码复现。与 ActiveLang 一起看，一篇改变采集、一篇改变保留，二者都不是语义 loss 直接改善几何的现成证据。

Discussion

Reading Questions

Does the method retrain the generator?

不需要。改变的是持久 memory 更新器，基础生成器和检索规则保留。

Are scores recomputed after every eviction?

不是。每次更新计算一次，在该轮删除中保持排序不变；下一轮有新观测后才重新计算。

Are the descriptors language-aligned semantic features?

不是。MemCam 使用 DINOv2 描述符，WorldMem 使用池化 VAE latent；论文没有语义教师或分割 loss。

Why can full retention still perform poorly?

保留全部证据消除了淘汰损失，但现有检索器可能选不中最佳证据，也可能反复使用已生成的错误。该解释由诊断支持，但不是所有检索系统的普遍定理。
