LingBot-Map: Memory for Streaming Reconstruction

Geometric Context Transformer for Streaming 3D Reconstruction

从一帧图像的处理过程讲起，拆解锚点、近期窗口和轨迹记忆；用原文消融解释每个设计的作用与容量边界。

At a Glance

  1. 任务：仅凭逐步到来的 RGB，持续预测相机位姿与深度。
  2. 方法：把历史分成固定锚点、近期密集窗口和六 token 的旧帧摘要。
  3. 证据：轨迹 token、时间编码和窗口机制分别有消融；压缩并非严格恒定容量。

Motivation

01 · Why Reconstruction Needs History

输入是一段不断到来的 RGB 视频。第 t 帧到达时，模型要输出这帧的相机位姿和深度，并把新结果放进与过去一致的坐标系。这里的“在线”指只能使用当前和已到达的帧；不是先看完整段视频，再逐帧播放结果。

只看当前图像，单目深度存在尺度歧义，相机运动也缺少跨帧约束。把全部历史图像 token 留下来又太昂贵：视频越长，缓存越大，每次查询要读取的信息越多。只保留最近几帧虽然便宜，但较早的空间参照会丢失，局部小误差可能不断累积成轨迹漂移。

作者的切入点是区分历史的用途。固定参考系、推断当前局部几何、约束长期轨迹，不一定需要同样细致的历史表示。因此，方法重点不是单纯扩大 memory，而是为不同几何需求保留不同粒度的上下文。论文展示的应用包括多房间行走、室外驾驶、航拍和生成视频，并不局限于绕某件物体拍摄。

Prerequisites

02 · Poses, Depth, Tokens, and KV Caches

相机位姿描述相机在参考坐标系中的位置和朝向。深度图为每个像素给出深度；有相机内参时，可以把像素反投影到相机坐标，再通过位姿变换到世界坐标。因此“每帧深度准确”和“全局地图拼得整齐”是相关但不同的要求。

token 是图像或状态的向量表示，不等同于对象。图像被切成小块后，一个 patch 对应一个向量；特殊 token 用于聚合信息，也不能自动解释为某个物体或某个三维点。

注意力里，当前特征生成 Query，用它和历史的 Key 计算相关性，再对 Value 加权求和。KV 缓存保存已经算过的历史 Key/Value，使下一帧无需重算过去的全部网络。缓存不是原图，也不是一份可以直接显示的点云。

ConceptPurposeCommon Confusion
位姿相机在哪里、朝向哪里？不是像素深度
深度像素对应的表面离相机多远？不直接给出全局位置
上下文 token未来预测还能读取哪些历史信息？不是显式对象目录
输出点云预测出的空间表面是什么？保存全部点云仍然会占用不断增长的内存

Architecture

03 · Figure 4: Following a Frame Through the Model

从图左侧开始：当前 RGB 经 DINOv2 初始化的图像编码器变成 M 个图像 token，再加入 camera token、anchor token 与四个 register token。接下来反复交替执行帧内注意力与 Geometric Context Attention（GCA）。

Frame Attention 让当前图像各个位置交换信息；GCA 则让当前特征读取允许访问的历史。图中三个 Context 不是三个独立重建网络，而是同一次跨帧注意力可访问的三类信息。注意力掩码决定“哪些信息允许被读”，学习到的权重决定“读到的信息怎样使用”。

最后，camera head 根据相机 token 预测位姿，depth head 从图像 token 恢复密集深度。当前帧的状态进入后续缓存；较旧帧离开近期窗口时，密集图像 token 被移除，少量特殊 token 继续保留。把这一步讲清楚，才能理解压缩发生在哪里。

Context Design

04 · Three Types of Context

Anchor Context：前 n 帧在初始化时相互使用完整注意力。它们的图像与相关 token 作为固定参照留下来。训练时，作者用锚点真值点云的平均距离归一化深度和相机平移，从而约定一个一致尺度。注意，这不是从任意单目视频中无条件获得物理米制尺度。

Local Pose-Reference Window：最近 k 帧保留完整图像 token。附近视角通常仍有较多可对应内容，密集历史有利于当前帧的相对定位与表面恢复。锚点提供“从哪里开始”，近期窗口提供“刚才看到什么”，两者承担不同作用。

Trajectory Memory：既不在锚点也不在窗口中的历史帧，每帧只保留六个特殊 token：一个 camera、一个 anchor、四个 register。它们保存供后续注意力使用的紧凑轨迹上下文，并结合时间位置编码。不能据此声称每个 token 已被监督成某种独立的几何变量。

关键区分：保留结构由设计规定；结构内的信息聚合通过训练学习。原方法没有让一个策略网络在任意历史 token 中自由选择“留谁删谁”，也没有对象语义驱动的实例级回收策略。

Memory Analysis

05 · Memory Budget: Compact Does Not Mean Constant

设每帧有 M 个图像 token 与六个特殊 token，总帧数为 T，锚点数 n、近期窗口大小 k 固定。忽略锚点与窗口在短序列初期的重叠，在长序列稳态下，上下文 token 总量如下。这里统计的是 token 数，而不是完整显存；实际 KV 字节数还要乘层数、特征维度、精度以及 Key/Value 两份状态。

代入原文举例 M≈500、n=3、k=16、T=10,000：全历史约有 5,060,000 个 token；GCA 约有 69,500 个。主要节省来自不再为每个旧帧保存 500 个密集图像 token。

但式子仍包含 6T，所以渐近复杂度没有变成严格 O(1)。更准确的说法是：增长斜率显著下降，在论文测试区间内可以表现得较为平稳。若我们研究严格固定容量 memory，必须进一步约束历史条目总数，并测试被丢弃信息是否影响后续预测。

全历史上下文：C_full = T(M + 6)
GCA 上下文：C_GCA = (n + k)(M + 6) + 6(T − n − k)
                         = (n + k)M + 6T

Training

06 · Training the Compressed State

训练先建立离线多视图几何能力，再引入 GCA，并逐步增加训练序列长度。原因很实际：若短距离几何还不可靠，一开始就展开很长轨迹，前面的误差会使后面的学习目标更加困难。渐进课程让局部几何与长程一致性分阶段成熟。

监督包含深度、绝对位姿和窗口内相对位姿。深度监督要求每帧表面正确；绝对位姿要求落在共同参考系；相对位姿关注窗口内帧间运动是否一致。例如两个相邻预测都偏向同一方向，绝对误差可能相近，而相对关系仍较稳定，反之亦然。两种约束不能简单替代。

历史特殊 token 没有单独被命名为“物体语义”，但后续帧要通过它们读取信息，重建损失会训练这条信息通路。这是任务驱动的隐式压缩：是否保留了有用信息，最终看后续位姿与深度，而不是看 token 的可视化是否好看。

实现层面的 paged KV cache 与 FlashInfer 用来降低缓存更新和注意力计算的开销。这属于系统效率贡献，应与 GCA 的信息保留结构分别解释。只实现掩码，不一定能复现论文报告的吞吐。

Experimental Evidence

07 · Experiments: Evidence for Memory

先理解指标：ATE 衡量整体轨迹偏差，越低越好；RPE 关注局部相对运动误差；FPS 越高说明处理越快，但必须绑定分辨率、硬件和推理模式。不同论文各自表格中的数字不能直接拼成统一排行榜。

原文 Table 6 在 TartanGround 验证集上做受控消融，评估 320 个采样视图、采样步长为 8。下面摘录同一消融中的三个配置。第一行到第二行更直接检验轨迹 token 的贡献；第二行到第三行说明时间编码也发挥明显作用。

轨迹 token 使 ATE 从 7.88 降至 7.46，降低约 5.3%；再加入 Video RoPE 降至 5.98。结论应该是“紧凑历史有效，而且时间组织也重要”，而不是“六个 token 独自带来了最终全部提升”。

Limitations

08 · Long Sequences: Direct Inference vs. VO

Direct 模式延续一个参考坐标系，直接输出网络预测。论文说明，大约超过 3,000 帧之后质量会逐步下降。VO 模式周期性重置局部重建，并用重叠区的 Sim(3) 对齐连接各段，适合更长轨迹。Sim(3) 包含旋转、平移与尺度，用于对齐两套局部坐标。

所以“支持超过 10,000 帧”不能自动翻译为“单个不重置 memory 在任意长度上不漂移”。理解长序列演示需要同时查看推理模式、关键帧设置以及是否做分段对齐。

这里也能看出任务边界：轨迹摘要足以帮助位姿，不代表足以恢复久远区域的全部细节；导出历史点云不代表网络内部长期状态还保存着这些细节。评估 memory 时应明确测的是预测状态，还是外部输出文件。

Discussion

09 · Contributions and Open Questions

这篇的核心贡献是按照几何用途组织上下文：锚点负责参照，近期密集窗口负责局部几何，轨迹摘要负责长期联系，并用相应训练与缓存实现把它变成可运行的流式系统。它提供了一个比“所有历史同等保留”更明确的基线。

我们的延伸问题可以很具体：六 token 摘要对哪些信息有偏好？当后续需要区域或对象级证据时，现有压缩是否会丢失必要内容？若语义监督改变的是记忆保留的信息，应该在相同总预算下验证后续重建和语义查询，而不是仅增加一个语义输出头。

一个可检验的后续实验是：固定主干、缓存容量和训练数据，对比几何监督与几何加语义监督；分别在短序列、长间隔重访和新环境上测试。当前论文没有提供这个语义实验，这属于阅读后提出的研究假设。

Discussion

Reading Questions

Do the six tokens represent six objects?

不是。它们是 camera、anchor、register 这几类特殊 token；原文没有规定对象级语义身份。

Is GPU memory usage strictly constant?

轨迹条目每帧增加六个 token。结构显著压缩增长，但不等于严格固定容量；外部累计点云还需另算。

Why keep recent frames as well as anchors?

锚点提供固定参考，近期视图提供更直接的密集重叠证据。固定参照并不保证当前区域有足够细节。

Can we already claim that semantics will help?

不能。需要证明语义改变了状态中保留的有效信息，并在相同预算和协议下改善后续任务。
