Geometric Encoding for Spatial Reasoning in Vision-Language Models

First submitted 2026-09-28 · Reading version 2609.34148v1

Geometric Code 将视频中的对象、深度、相机和房间结构转换为显式 spatial code，再通过 prompt 辅助 VLM。四个开源模型在 frames+code 条件下平均准确率由 53.1 提升到 57.1，绝对距离任务提升最明显。

At a Glance

  1. 几何代码是可检查的外部表示，不是隐式语义 memory。
  2. frames 与 code 互补，code-only 不能替代视觉上下文。
  3. 适合定义 LingBot-Map 的几何/语义读取接口与对照。

Paper Notes

Task and Spatial Code

VLM 对视频中的对象识别较强，但对距离、尺寸、出现顺序和跨帧身份推理不稳定。论文把这些空间量显式化，输出对象位置、尺寸、数量、两两距离、出现顺序和房间几何。

输入为单目 RGB 视频和数据集对象词表；SAM-3 给出实例 mask，DA-3 给出深度、位姿和内参，deterministic geometric engine 反投影、合并和清理点。

Reading the Pipeline

图 1 的流程是 perception → geometric engine → prompt augmentation。对象检测在每帧独立进行，系统通过几何和外观规则跨帧合并；尺寸从最佳观测估计，室内轴向使用重力和 PCA。

最终 VLM 可以看到 frames only、code only 或 frames+code。这样能把几何信息是否被使用与 VLM 自身的视觉识别分开。

Experiments and Ablations

在 VSI-Bench 上评估 Qwen3.5 和 InternVL3.5 的 2B/4B 版本。四模型平均 frames-only 为 53.1，code-only 为 53.3，frames+code 为 57.1；Qwen3.5-2B 从 45.1 提升到 54.3，InternVL3.5-4B 从 56.9 提升到 61.0。

绝对距离任务的 frames-only 为 34.2–43.2，code-only 为 65.4–67.3。相反，object count、size 和 appearance order 仍需要原始视觉，code-only 可能下降。

Code only53.3Explicit geometry
Frames + Code57.1Complementary evidence

Paper Notes

Training and Interpretation

方法没有训练或 fine-tuning；提升来自预训练感知模型和确定性几何计算。对于直接可计算的 metric 任务，VLM 更像读取空间代码，因此不能把全部提升解释成更强的语言推理。

这篇工作证明的是显式几何接口有用，不是语义融合改善三维重建。错误的深度、相机或跨帧合并会直接污染代码。

Paper Notes

Transfer to LingBot-Map

可以把当前帧和历史 token 聚合成 region/object code，用于解释 memory 读写：当前查询需要哪个区域、哪个历史观测、哪个几何量。

但是必须对比 raw visual、geometry-only、semantic-only 和 geometry+semantic，保持缓存容量、帧数与解码预算一致。若只改善下游空间问答而未来帧深度不变，就不应称作重建收益。

Discussion

Reading Questions

Is code-only enough?

不够。它适合度量问题，但计数、外观和复杂多选仍需要视频。

Is this semantic memory?

不是。它是显式几何上下文，没有长期可学习写入机制。

How does it guide our design?

提供可检查的 memory read 接口，并强调输出收益与重建收益要分开。
