Semantic Memory for Streaming Reconstruction: Discussion Notes

Advisor discussion · Motivation, model, and first experiments

想和老师聊清楚的一件事：同样保留这么少的历史，能不能让模型记住更有用的信息？我想从语义参与 memory 的形成入手，先验证它是否真的帮助后续重建。

At a Glance

  1. 切入点：旧帧密集信息被丢掉后，少量历史 token 到底还保留了什么？
  2. 做法：先预测像素对齐的语义，再与视觉特征融合，让共享注意力据此形成历史状态。
  3. 先看一个结果：写入前融合，是否比只在当前输出端使用语义更有利于后续几何。

Discussion Notes

01 · The Idea I Want to Explore

老师，我想做的其实比较集中：还是沿着 LingBot-Map 做 RGB 流式重建，但让语义真正参与历史信息的保存和使用。我希望最后不只是地图上多了一层语义颜色，而是加了语义之后，后面的几何也能做得更好。

我觉得值得切进去的地方是它的历史压缩。近期帧还保留密集图像 token，但旧帧最后只剩六个特殊 token 的 KV。这样很省，但也意味着大量信息被丢掉了。我想问的是：同样留下这几个向量，有没有办法让它们保存对后续重建更有价值的信息？

我的想法是，在这些历史向量形成之前就把语义放进去。这样研究的重点就比较明确：语义能不能帮助模型形成更有用的历史，而不只是增加一个分割输出。这里是我想验证的方向，还没有实验结果。

Discussion Notes

02 · Why Semantics Might Be Useful

比如相机连续移动，同一块区域的视角、光照和纹理表现都会变。只靠局部外观，有些区域可能不好区分。我希望语义能补充一层信息：这些局部特征大致属于什么区域，它们在内容上有什么区别。这样模型在聚合历史时，可能更容易保留后面还用得上的线索。

但我不打算按类别去硬匹配。两扇窗的语义可以很像，却不是同一处；同一个物体也不意味着表面深度相同。所以语义只作为补充，原来的视觉和几何信息都保留，让网络在几何任务的约束下学习怎么用它。

已有工作里，ConceptFusion 给我的启发是语义特征可以对齐到像素并进入三维地图；SLARM 则让我觉得，重建过程中加入密集语言监督是可以借鉴的。但它们不能直接回答我们的问题：这些语义到底有没有改善 LingBot-Map 的历史表示，以及之后的几何。

Discussion Notes

03 · What I Would Change in the Model

具体实现看这张图。主干还是 LingBot-Map，我先不动它的缓存策略，也不额外搭一套重建网络。当前 RGB 编码后得到视觉特征，再接一个小的语义预测器，在相同位置预测语义向量。

然后把语义投影到主干维度，加回视觉特征里。这里用一个可学习的门控控制注入强度，原来的视觉特征作为残差保留下来。关键在于，这个融合放在共享上下文之前，而不是最后输出深度之后才附加语义。

这样，帧内注意力聚合图像信息、特殊 token 形成摘要的时候，就已经接触到语义了。后面保存的 KV 自然有一条依赖语义的前向路径。未来帧仍然通过原来的 GCA 读取它，预测深度和位姿。

所以我想改的是“写进去的内容”，不是先把 memory 做得更大。旧帧仍然保留原来的特殊 token，推理多出来的是轻量语义预测器和融合模块。到底增加多少时间、同样的缓存下效果怎样，都可以比较清楚地测出来。

04 · How I Would Train It

语义不需要人工一帧一帧标。我准备先用冻结的密集语言对齐教师，比如 LSeg，给出像素对齐的特征目标，再把它蒸馏到这个小预测器里。教师只在训练时使用，部署时不需要每帧再跑大模型。

训练目标先保持简单：第一项是原来的深度和位姿损失；第二项约束融合前的语义预测，让它确实学到教师的语义；第三项约束上下文之后的语义输出，让最终表示也保留语义能力。之前讨论的 memory reconstruction loss，我先不放进这版，避免一下子改太多。

我觉得最重要的是，几何损失能沿着共享上下文回到融合模块。展开连续帧训练时，后面一帧如果用了前面的 KV，它的几何误差还可以回到前面那帧形成历史的过程。这样模型学习的不是“尽量多存语义”，而是“怎么用语义形成对几何有帮助的历史”。这要求训练时的历史状态可微，不能直接拿 detach 后的推理缓存来训练过去的写入。

05 · The Experiment I Would Run First

我想先做的不是把完整系统搭得很大，而是抓住一个最关键的对照：同样都有语义，一个只在最后解码时融合，另一个在历史形成前融合。前者增强当前输出，但融合结果不写回缓存；后者让语义参与历史形成。

如果写入前融合更好，尤其是在需要较早历史的后续帧上更好，那我们才有理由继续沿 memory 深挖。如果两者差不多，就说明现在的收益可能主要来自当前帧增强，不能把它讲成历史记忆的提升。

另一个必须排除的是“只是多了参数”。所以会加一个同规模普通特征分支，也会用非语言视觉教师做对照。正确对齐的语义和打乱的语义可以辅助检查模型是否真的依赖区域信息，但这种破坏实验会改变输入分布，不能单靠它下结论。

几何评测同时看深度或点云精度、完整度、轨迹，以及速度和显存。语义分割变好了当然有价值，但不是这条主线的最终答案。我最想看到的是：相同缓存配置下，语义参与历史形成之后，后面的几何有稳定增益。

Discussion Notes

06 · What Would Make This Worth Pursuing

我觉得这个方向有意思的地方，是把语义从“重建的附属输出”变成“历史表示形成时的一种信息来源”。我们真正想回答的是，流式重建在必须丢掉大量历史的情况下，什么信息值得进入留下来的状态。

当然，门控和蒸馏本身都很常见，所以我不会只拿“加了一个语义分支”作为创新。能让这个工作站住的，是先定位历史利用上的问题，再证明写入前语义融合确实有帮助，而且这个收益不能被额外参数或当前帧增强解释。

所以我想先把几何基线、输出端融合、写入前融合这三个版本跑起来。要是这个关键对照成立，就继续看哪些历史条件下收益最大，再决定要不要进一步改状态保留方式。要是不成立，我们也能很快知道，是语义没有贡献，还是融合位置没有带来额外历史收益。

最后的输出仍然是几何加对齐语义，后续可以做开放词汇查询。实例关联和动态分解先不一起塞进来。我想先把“语义能不能让同样的历史更有用”这件事做扎实。

Discussion

Reading Questions

Why should semantics help geometry?

现在的理由是它可能补充对外观变化较稳定的区域信息，帮助历史聚合与读取。这是机制假设；是否真的有效，要看写入前融合相对输出端融合的几何结果。

Is this just another feature-fusion module?

如果只有整体精度稍有提升，那确实不够。需要定位历史压缩或利用中的具体问题，并用匹配对照证明语义在这个位置的作用。

What does the first implementation need?

同预算几何基线、冻结教师特征、轻量语义预测器、门控投影和上下文 adapter。先不增加对象槽位、在线 BA 或 memory reconstruction loss。

What is the most useful feedback to ask for?

老师是否认可先用“输出端融合 versus 写入前融合”判断历史收益，以及优先选什么数据与历史间隔来暴露基座的问题。
