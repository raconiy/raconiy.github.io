Code World Model 2.0: Towards Infinite Controllable Video Generation

Ruoyu Wang et al. · arXiv:2611.22925v1 · First submitted: 2026-11-17 · Read version: v1

Code World Model 2.0 用多粒度结构代理、外观参考和语言构成统一控制接口，再用 Progressive Forcing 训练四步 causal streaming renderer。

At a Glance

  1. 结构代理可从粗布局到细几何，模型在同一接口下根据可用证据补足局部运动。
  2. ProForcing 从 teacher forcing、resampling forcing 到自生成 rollout，逐步处理少步去噪和历史漂移。
  3. 约 200 小时数据、140 个 streaming rollouts 和 30 分钟 racing rollout 支持长时序控制，但仍依赖代理质量。

Problem Setup

01 · Why Proxy-Conditioned Streaming Video Needs a New Training Recipe

Code World Model 2.0 关注一个工程上很现实的矛盾：交互生成既希望用细粒度几何代理控制相机和对象，又希望在流式模式中只用少量因果去噪步骤，并且不因自生成历史而逐渐漂移。粗代理便宜但约束弱，细代理约束强但构建和传输成本高。

作者提出 Invoker-Render，使用同一个 conditioning interface 接受结构代理、appearance reference 和 language；模型根据当前交互需要选择代理粒度，而不是为每种控制重新训练一套 renderer。

Method

02 · Method: Shared Interface for Multiple Proxy Granularities

代理可以是 semantic layout、root trajectory、shaded geometry 或更细的 articulated structure。细代理存在时，模型应遵守明确几何；只有粗代理时，模型需要补出局部运动和外观。这个设计把“输入证据的粒度”作为显式变量，而不是把所有条件强行统一成同样密度。

双模型共享接口：bidirectional creation model 处理完整 clip 和未来条件；causal four-step streaming model 逐块生成，只读取当前 proxy chunk、局部文本和保留的视觉历史。它们共享 appearance 和 language 组织方式，因此离线创作与在线续写可以使用相近的控制语义。

Training

03 · Progressive Forcing and Serving

ProForcing 是论文最值得读的训练部分。先用 teacher forcing 训练 block-causal predictor，再用 resampling forcing 构造带噪和不完美的 history；之后用 RF-DMD 和辅助 GAN loss 将模型蒸馏到四步 renderer，最后在 continuous self-generated rollouts 上继续训练 student、score model 和 discriminator。

这条课程的直觉是先学会条件生成，再逐步暴露部署时会遇到的历史误差。如果一开始就在四步自回归 rollout 上训练，模型同时面对条件学习、少步去噪和 exposure bias，优化信号会混在一起。服务端还复用窗口内计算，并把 proxy encoding、视频解码和 RGB 输出流水线化。

Experiments

04 · Evidence: Long Streaming Under Mixed Granularity

作者使用约 200 小时的多粒度对齐语料：150 小时自采数据、50 小时公共数据，每个片段同时关联 RGB、结构代理、外观参考和层级文本。实验覆盖 140 个 streaming rollouts，并比较视觉质量、结构遵循和 reference preservation。

摘要和实验结论报告相对近期 streaming baseline 的一致提升，并展示 30 分钟 racing rollout 中场景和主体外观仍能维持。这里的关键证据不是单个短片的清晰度，而是 coarse-to-fine proxy 切换后仍能工作，以及四步 causal renderer 在长时间历史中没有快速坍塌。

论文没有把“30 分钟稳定”解释成世界状态永远正确；它仍依赖 proxy 序列、训练数据覆盖和 serving stack。对于开放世界交互，代理估计错误仍会直接限制结果。

Discussion

06 · Limits and Connection to Our Direction

这篇工作对 LingBot-Map 的启发是把 memory 读写和输入证据粒度联系起来：语义 token、几何 token 和局部实例轨迹不必每帧同等密度保存，当前重建任务可以按视角变化和不确定性读取不同粒度的历史。

但视频生成和流式重建的目标不同。Invoker-Render 的输出是具有外观一致性的未来视频，LingBot-Map 需要 metric depth、pose 和点图。若迁移到重建，必须把“结构代理遵循”替换为几何误差、跨帧对齐和完整度评估，不能只看视觉观感。

Discussion

Reading Questions

Why support multiple proxy granularities?

因为导航只需要粗布局和根轨迹，而近距离交互需要 articulated geometry；统一接口让输入细节随任务变化。

What problem does ProForcing solve?

它逐步把训练从干净历史推进到不完美和自生成历史，缓解四步蒸馏与长 rollout drift 同时出现造成的训练不稳定。

Does 30-minute rollout prove persistent world memory?

不能完全证明。它证明外观和主体在该数据和控制设置下能维持较长时间，但显式可回溯状态与 metric 3D 持久性仍是另一问题。

What is the relevance to semantic-guided reconstruction?

语义可作为一种粗粒度结构代理，几何 token 作为细粒度代理；读取粒度可随不确定性和视角变化调整，再以深度和位姿损失检验是否真正有用。
